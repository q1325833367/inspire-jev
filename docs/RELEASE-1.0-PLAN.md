# 1.0 发布与验收计划

正式发布要求同一份安装包通过真实宿主业务验收。开发测试、平台冒烟和历史实验分别保留，不转换为正式成绩。

## 发布范围

- 共享 Node.js 核心、桌面插件、Pi 原生扩展、stdio MCP。
- 桌面独立浏览器路径须明确标注；不宣称替换宿主内部 Computer Use。
- Pi 沿用既有模型路由；首发验证官方 zai GLM 5.3。
- 模型与浏览器分别配置代理，TUN 关闭。
- 每个宿主保持独立身份、登录档案和权限，不复制个人浏览器 cookies。
- 主 Agent 规划与核验完整要求，Jev 选择实际候选；明确输入和唯一目标直接处理。
- 侧栏适配、远程 HTTP、其他执行器及市场发布不进入本版发布门槛。

## 冻结业务集合

三个入口分别运行以下六项任务，每项三次，共 54 次。

|用例|任务与检查|
|---|---|
|Wikipedia 字段|搜索 Alan Turing，采集标题、出生、教育、主要贡献及来源，检查完整性|
|Wikipedia 章节|通过目录定位 Death，核查标题、首段与章节来源|
|Gutenberg 作者|搜索 Charles Dickens，按现场顺序核查前三本身份、详情、格式并返回|
|Gutenberg 榜单|读取昨天前十项下载数，由代码排序，保留现场顺序和来源|
|GitHub 公开仓库|读取 browser-use/jev-ultrafast 的 README 前 1500 字及完整许可证和来源|
|GitHub 私有草稿|给定名称、生成一句中文描述、选择 Private，停在未提交状态|

私有草稿禁止创建仓库。生成描述为 20–60 字的一句中文工具用途说明；给定文字直接填写。每入口至少 17/18 完整业务成功，分别报告 Jev 独立与含接管成绩。

三个入口各运行一次 Gutenberg 27 本长任务：首页进入昨天榜单，现场发现书目，逐本核查身份、详情、可用格式并返回。至少 55 次实际动作；观测、截图、采集和续跑不凑数。缺项如实记录，不换书或预载答案。旧严格文字阅读失败保持原分类。

十条不包含 Jev 名称的自然请求至少 9 条正确优先选择 Jev；桌面分配 01/02/06/10，Pi 分配 03/04/07，CLI 分配 05/08/09。原生工具仍可用，报告各入口实际成绩。

## 速度对照

桌面 18 组同要求对照，交替采用基线先、混合先。两侧使用干净主模型上下文、同模型、同适配器、同档案和相同就绪条件。基线逐次执行新鲜目标，不使用 run/resume；混合正常连续执行及接管。

端到端计入规划、工具往返、等待、模型选择、文字生成、接管及独立核验。中位数不超过基线 80%，P95 不超过基线 110%；nearest-rank，18 个样本对应最大值。全部 18 组两侧均须完整通过，因此该轮桌面业务实际要求 18/18。

混合侧同时计入桌面 18 次业务，另增 18 次基线；加上 54 次业务、3 次长任务与10次自然请求，共85次正式任务运行。对照期间不运行其他模型或浏览器测试，不选择性清缓存或预热。方法偏离及现场实质变化保留原记录。

## 执行与证据

普通核心预算90秒/40动作，片段最多45秒；长任务15分钟/200动作。宿主总等待上限普通5分钟、长任务30分钟。超时先取消并核对状态，不直接杀死浏览器或重放。

每次记录轮次、任务、入口、模型、包与工具指纹、允许来源、会话与运行编号、时间戳、单调计时、动作、接管、模型用量、来源、独立检查和证据SHA256。不可查询的模型用量或后端版本注明未测。

原生调度器不提供答案或网页操作序列；SDK测试不算原生验收。业务与安全计数由事件和只读检查器产生，不能手工指定通过。独立核验不只信任 verified。

正式记录追加保存，失败不能被重试覆盖。诊断与补跑使用单独编号。运行代码、工具或检查器变更后新建候选轮次，重新冻结并重跑正式集合。仅外部报告补充不改变验证包。

## 平台与故障验证

macOS：原生桌面与CLI、登录态和生命周期。Windows11ARM64：原生Pi、MCP、取消恢复与生命周期，明确Chromium架构。LinuxARM64：独立容器的原生Pi完整公开流程，保持非root和Chromium沙箱。六平台CI仅作为核心与网页适配器证据。

回归覆盖大页分批、截断、重渲染、重复标签、嵌套滚动、iframe、已知值、取消、确认丢失、重启、互斥、用户改变现场、网页诱导、代理失败、追踪容量和动作核验。

三系统分别验证：新用户安装、隐藏key配置、无文本模型公开读取、双代理、脱敏诊断、真实任务、修改key、升级、回退、重装、单入口卸载、全部卸载和实际服务版本。隔离测试目录，不破坏日常安装。

Windows保留现有评估VM与恢复点，用户目录操作使用登录用户身份；批量Guest Agent操作，避免高频启动UTM。仅共享测试目录，记录评估期限并于到期停用。

## 日志与清理

正常颗粒追踪关闭，无可视化。测试JSONL记录分层耗时，不记录密钥、输入实值、登录信息或完整页面。私有表单保存匹配结论，公开截图遮蔽账号。

运行中、待查、固定、效果未知证据受保护；已排查日志按7天、20份及容量规则清理。保护数据超限时报告占用，不删除待查证据。已完成且无未知效果的检查点7天后可清理。未完成检查点保留。

1. 源码、历史、安装包与附件扫描。
2. 核对正式54次业务、零安全违规、三长任务、默认选择、18组对照、三系统流程及生命周期。
3. 生成中文与机器报告，验证包、协议和报告指纹。
4. 核对合并未改变已验证运行文件，六平台CI通过。
5. 建立v1.0.0标签和草稿Release，上传已验证包、清单、校验和与脱敏报告。
6. 下载核对远端附件；校验双语文档与安装链接。
7. 守卫全通过才发布stable；不通过保持RC。
8. 本机入口切换同一正式包，核对工具与原档案，各完成发布后真实冒烟。
9. 关闭追踪，归档本轮验收对话，保留回退与失败历史。
