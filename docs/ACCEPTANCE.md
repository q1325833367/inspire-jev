# 正式验收与发布守卫

正式 1.0 使用 `public-1.0` 范围：同一候选安装包经过三个原生入口，各完成 Wikipedia 字段、Gutenberg 作者前三本、GitHub 公开仓库三项完整任务，共九项，全部通过。三系统真实流程及安装生命周期、零错误完成、零越权操作、零不确定提交重放仍为门槛。登录表单和批量性能对照不作为首发门槛，也不宣称已证明提速。开发验证、平台 CI、构建和单测均不计入正式成绩。交付操作见 [1.0 计划](RELEASE-1.0-PLAN.md)。

## 独立轮次

每轮使用 `artifacts/acceptance/1.0-r01/` 等独立目录；原始证据留在本机，不进入源码或安装包。冻结文件以独占创建写入，不允许覆盖。失败保留原编号，诊断和重试不能替换原成绩。运行代码、任务或检查器变化时建立新候选轮次并重新验收。

```sh
npm run acceptance -- prepare --round 1.0-r01 --scope public-1.0
npm run acceptance -- preflight --round 1.0-r01
npm run acceptance -- freeze --round 1.0-r01
npm run acceptance -- run --round 1.0-r01 --entry pi
npm run acceptance -- compare --round 1.0-r01 --entry gpt
npm run acceptance -- long --round 1.0-r01 --entry codex-cli
npm run acceptance -- route --round 1.0-r01
npm run acceptance -- report --round 1.0-r01
npm run acceptance -- verify --round 1.0-r01
npm run acceptance -- promote --round 1.0-r01
```

退出码为通过 0、失败 1、外部依赖阻塞 2。桌面运行命令建立待调度任务，由桌面验收控制器创建真实对话并采集宿主事件；排队不等于完成。Pi 和 CLI 调度使用原生命令，保留原生工具，不能用 SDK 循环代替主 Agent。

候选身份包括安装包 SHA256、实际运行目录构建指纹、工具定义指纹和来源提交。冻结内容还包括检查器、完整目标、模型设置、档案、自然请求及对照顺序。已安装版本不能代替运行版本核对。

## 扩展业务集合（不作为公开网站首发门槛）

每项在桌面、Pi、Codex CLI 各重复三次，共 54 次。

私有草稿禁止创建仓库。名称使用冻结轮次、入口和重复编号。登录只使用该宿主已有持久档案；未登录只阻塞私有用例。完成登录后核验关闭、进程重启和新会话仍登录，不复制 cookies。

每入口另执行一个 Gutenberg 长任务：从现场昨天榜单发现前27本，逐本核查详情与所有可用阅读格式，每本后返回。至少55次实际导航或交互；观测、截图、采集和续跑不计动作。缺项记录，不替换书目。旧 PoC 的失败保留原分类。

## 原生证据和独立核验

原生事件与测试观察器以参数、结果摘要关联；观察器不增加模型工具，也不向模型提供额外状态或答案。检查器读取有限业务字段及阶段采集结果，不能只相信 `verified`。

事件记录时间戳、单调计时、关联编号和操作边界。原生宿主往返、浏览器执行、模型用量和接管均进入端到端记录。主模型用量不能取得时标为未测。输入实值、key、登录信息和完整页面不进入追踪；私有表单保存匹配结果与摘要。

证据使用追加哈希链，截断、修改和对应关系缺失均拒收。正式记录从真实事件派生；不得手填宿主调用通过、业务通过或安全计数。报告同时列出通过、失败、待运行、阻塞和拒收原因。

## 扩展默认选择与速度对照

十条冻结自然请求不提 Jev：桌面 01、02、06、10；Pi 03、04、07；CLI 05、08、09。记录首个相关工具选择、原生工具可用性及业务结果；总计至少9/10优先选择 Jev，分别报告入口成绩。

桌面18组对照复用该轮18次混合业务运行，额外增加18次逐步基线。主模型、适配器、档案和初始状态一致；按组交替先后顺序。基线每次由主模型决定一个新鲜目标动作，不使用 run/resume。两侧均计入规划、等待、文本生成、接管和完整核验；对照期间暂停其他测试。

18组两侧业务必须全部通过。混合端到端中位数不得超过基线80%，P95不得超过基线110%；nearest-rank 在18个样本时取最大值。成绩名称为“同适配器逐步执行对照”。方法偏离和不可比较记录保留。

首轮正式任务总数为85：54次业务、18次额外基线、3次长任务、10次自然请求。平台、恢复和安装生命周期另行取证。

## 提升与保护

公开网站首发要求每入口3/3、总计9/9，以及三系统实际流程和生命周期通过。`extended` 范围另要求每入口至少17/18、三个长任务、默认选择、完整对照与速度门槛。所有正式运行的错误完成、越权操作和不确定提交重放必须为零。

`promote` 重新计算证据和门槛，仅通过后生成 stable 清单，并附冻结协议及报告哈希。稳定候选在通过前只标记 candidate；版本字符串不能获得 stable 状态。发布必须上传该份已验收包，禁止重新打包替换。

正常使用不启用观察器或颗粒追踪，不提供日志可视化。测试证据在轮次结束前固定，待查、运行中和未知效果受保护；容量达到上限停止记录并报告，不能删除未查明资料换取继续测试。已排查资料和已完成且无未知效果的检查点按既定七天保留规则清理。
