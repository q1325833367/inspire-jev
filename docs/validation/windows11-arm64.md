# Windows 11 ARM64 开发验证

日期：2026-10-06。验证包：`1.0.0-rc.6`，SHA-256：`2eda16c155b2391f33d16af1248dc912840b3b994e7e425291fe48e624b74eba`。该记录属于开发验证，正式验收进度仍为 0/54。

## 环境与安装

- Windows 11 IoT Enterprise LTSC 2024 ARM64，构建 26100，微软 90 天评估许可已激活。
- UTM 4.7.5，8 个虚拟 CPU、16 GB 内存、128 GB 动态磁盘；Secure Boot 开启，TPM 2.0 设备及启用状态通过原生查询确认。
- Node.js 24.19.0 ARM64；Chromium 的 PE Machine 为 `8664`，使用 Windows x64 模拟。
- Pi 0.84.3：`@earendil-works/pi-coding-agent`；主模型为官方 zai `glm-5.3`。Codex CLI 0.160.1 已安装并注册 MCP，其模型工具调用尚未在此虚拟机验证。
- 从发布 tgz 安装 Pi 与 stdio MCP 同版核心。使用标准用户目录、独立浏览器档案和当前用户权限；未导入个人浏览器 cookies。
- TUN 关闭；模型和浏览器使用显式 HTTP 代理。Jev 实际模型为 `jev-1.13.0`，文字诊断返回 `deepseek-flash`。正常配置关闭颗粒追踪。
- 干净系统与工具安装完成各有一个经停机、文件比对确认的恢复副本，均在导入模型凭据之前创建。

## RC.7 修复与待验证项

RC.7 在公共接口拒绝冲突引用，并在仅剩多元素歧义检查时直接返回 `ambiguous_check`。独立浏览器保存有限的已观测导航链，重启后验证当前现场再返回已知目的地，不重放旧动作或 POST。

RC.7 本机 macOS 61 项回归通过，实际 stdio MCP / Jev Books 流程通过：3 次动作、0 次接管、独立原始目标检查及幂等性通过，端到端 5,340 ms，核心 2,333 ms。该结果只用于修复回归，不与 Windows 或内置侧栏进行速度比较。

Windows RC.7 的升级、回退、卸载及完整长任务恢复需要实际发布包复测。平台正式成绩仍要求真实主 Agent、冻结任务、独立检查及全部失败记录；构建和开发 SDK 成绩不能替代。
